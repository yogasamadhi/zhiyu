## 在验证中修复的实际问题

- 部分更新误用带默认值的 schema，导致只修改名称时重置其他配置；改为明确的可选更新字段。
- 同一草稿创建请求短时并发时把“处理中”误报为冲突；相同幂等请求现在等待并重放同一结果。
- 原始数据版本整数类型识别及保留字段重命名，导致分析选择器字段不兼容；现在使用物理字段名提交、来源名称显示。
- 差异比较忽略起始运行、分页导致统计不全；现在重放两端历史状态后统计完整差异。
- 语料预览失败占用幂等键、构建完成后结果列表未刷新；已补齐重试和结果刷新。
- 分析/语料“导出”只取得元数据，以及 Desktop 保存拒绝分层 Artifact 路径；现在真实生成/保存文件，并校验目录约束及拒绝路径穿越和符号链接。
- 菜单继承普通折叠区域边框、次要文字对比度不足、窄屏导航关闭后焦点丢失；已在真实界面检查中修正。
- 创建请求幂等重放返回旧草稿状态，导致再次创建时恢复已提交或已删除草稿；现在恢复前读取最新状态，并在提交后清理创建入口标识。
- 无限滚动触发点已处于视口内时不再触发加载；现在先让触发点离开视口再滚动到底部，连续确认内容稳定后停止，并新增真实浏览器回归用例。
- 运行结果已完成而任务状态尚未刷新时，详情偶尔停止轮询；现在同时依据任务和运行状态继续查询。
- 开发启动器注入 `VITE_FIXTURE_URL` 后，任务编辑器和输出页把开发地址保留在生产包中，触发 Desktop 构建检查。两处现在使用编译期条件移除生产包中的开发配置；保留原构建检查。新增 2 项真实 Vite 构建测试覆盖默认和备用端口，与原有 2 项开发样例测试一并通过；UI/Desktop 类型检查、相关 lint/格式检查及当时的 `bun run.ts --skip-install` 实际启动通过。当前等价入口为 `bun run-desktop.ts --skip-install`。此补充回归不计入上表此前的 478 项全量测试结果。

## 验证边界与运行环境说明

- 测试使用新建的独立临时数据库和临时 Desktop 用户目录，结束后清理本次创建的资源，不重置原开发数据库。原开发数据库曾报告已有 `monitoring:002` 迁移校验和不一致；本轮未篡改其迁移记录，使用该数据库前仍需核对它对应的历史版本。
- 本机只验证 macOS arm64。macOS x64、Windows 和 Linux 发布目标仍由现有 CI 矩阵执行，本文不声称这些远程任务已运行。
- AI 草稿协作通过契约与脚本化 Provider 测试。真实外部模型连接需有效模型凭据；未使用个人生产凭据做外部调用。
- 未添加招聘平台实际授权同步适配器，也未对外发布、配置正式证书或接入外部统计平台。
- 真实用户研究尚未开展。测试脚本与指标口径已交付，不能用内部自动化通过率替代真实用户完成率。
