# 织云助手实施计划

> 2026-09-10 更新：本文中的浏览器工作台、Headless 启动和独立发行内容属于历史方案，已由 [应用入口收敛决策](../adr/0011-desktop-cloud-apps.md) 替代；本地 Runtime、SQLite、插件与 Worker 的边界继续保留。

编写日期：2026-09-09。实施更新：2026-09-10。助手代码已落地并进入综合验收。本计划保留设计基线；实际实现、接口补充和验证状态见 [助手实施与验收记录](assistant-acceptance.md)。真实模型与真实小白验收单独记录，不以自动化测试替代。

产品目标：用户无需事先创建任务、提供网址或理解采集技术，就能通过聊天明确目标、获得真实数据、学习操作，并在后续使用中获得持续帮助。

实施覆盖 Web、Desktop 和共享 Product API，沿用当前 Level 2 Internal Plugin Runtime、统一 Collection Draft、pi 引擎和现有模型配置。

## 1. 完成标准与范围

完成以下用户路径，才算完成本计划：

1. 用户只有一个想法，助手通过少量必要提问协助选择来源、确定字段、获得真实预览、保存运行并使用结果。
2. 用户已有网址，助手直接利用该网址推进，用户可以在聊天和表单之间修改同一份草稿。
3. 用户没有创建意图，可以独立提问、学习；聊天和学习不会附带创建业务草稿或任务。
4. 用户可以随时切换“带我完成”“帮我处理”“教我操作”，保留当前目标和进度。
5. 用户在任务、数据和运行页面打开助手，助手根据明确的资源上下文提供帮助；任务创建后仍可继续对话。
6. 用户完成一个内置练习，助手根据真实界面事件和业务结果反馈，并能在用户请求时接手当前步骤。
7. 用户遇到采集或输出失败，助手解释有依据的原因，提供可执行的恢复路径；能区分采集失败与输出失败。
8. 未连接模型时，用户仍能完成明确标识的固定引导和离线样例；连接模型后回到原来的会话或草稿。

本轮以现有采集任务、草稿、数据集等资源为基础，不新增独立的“项目”业务层。助手支持现有分析、语料、输出能力的解释和引导，不扩展新的采集引擎或外部平台适配器。模型由现有 Provider 配置提供；托管模型额度、计费和模型市场不纳入本轮。

## 3. 先固定的产品和技术决策

### 3.1 交互约定

- 默认“带我完成”。“帮我处理”和“教我操作”是可随时切换的偏好，不增加首次使用的必选步骤。
- 每轮优先只问一个阻碍下一步的问题；已经提供或已由工具确认的信息不重复询问。
- 能可靠推断的字段先给可编辑建议；出现业务歧义时，展示例子请用户选择。
- 先获得小量真实预览，再补充正式采集范围、任务名称、计划和输出。
- 对概念采用“短解释 + 当前例子 + 可选操作”；只有用户要求时才展开完整说明。
- 已明确授权的读取、检查、小量预览和受限草稿修改连续完成；任务创建、正式运行、计划修改和外部输出通过具体操作卡触发。
- 用户纠正目标、来源或字段后，更新结构化状态，使不再适用的预览和操作卡失效。
- 用户看到的是“正在查看页面”“正在检查价格”等动作状态；技术日志按需展开。

### 3.2 产品入口

- 首页提供“已有网页”“只有想法”“先学一下”“体验样例”四个入口及自然语言输入框。
- 新增独立助手地址 `/assistant`，支持通过 `conversation` 参数恢复会话。
- 全局侧栏与独立页面共用会话控制器、消息渲染、取消/重试和卡片组件。
- 任务配置、任务详情、运行详情、数据集页面提供带资源引用的“解释这里 / 帮我检查”。
- 侧栏显示当前帮助对象；当前页面变化作为候选上下文，不能静默替换正在修改的目标。
- 用户主动从某个页面发起就地求助时，明确绑定该对象；绑定变化后重新校验操作卡。
- 旧 `/crawler-assistant` 和 `/tasks/new?...&assistant=1` 链接通过适配入口保留会话、草稿和返回位置。

### 3.3 pi 与业务边界

pi 负责模型循环、工具选择、流式事件和中止；助手服务负责上下文组装、偏好、知识、教学进度和操作协调；业务插件继续拥有草稿、运行、数据和输出。通过 Contract Port 和组合层调用，不跨插件读取业务表。

工具目录按照活动 Profile、用户权限、资源状态和帮助方式生成。模型建议不能绕过服务端权限或版本校验。继续使用当前 pi 版本；若实施中需要新 API，单独核对版本并验证适配，不把升级作为默认前置条件。

保持现有单 Agent 主循环，通过工具和知识包提供不同能力。本轮不建设多 Agent 调度、第三方插件宿主、向量数据库或 RAG。

## 4. 状态、持久化与兼容设计

以下为待落地的领域契约，先在 P0 固定，再开始迁移与接口开发。

| 对象                      | 必要信息                                                         | 约束                                                                       |
| ------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `AssistantConversation`   | 标题、生命周期、帮助方式、所有者/访问范围、revision、时间        | 生命周期为 `active / archived`；不以任务成功或 Turn 失败结束会话           |
| `AssistantTurn`           | 消息、状态、attempt、工具与模型用量、错误、执行时间              | 沿用 queued/running/succeeded/failed/canceled；同一会话一次只执行一个 Turn |
| `AssistantContext`        | 意图、当前资源引用、目标摘要、待解决问题、上下文 revision        | 意图是可切换标签；资源引用可为空，正文和原始凭据不作为上下文缓存           |
| `AssistantResourceLink`   | conversationId、资源类型/id、关联用途、关联时间                  | 会话可关联多个结果，但只有一个明确的当前操作目标                           |
| `AssistantMessageBlock`   | 类型、版本、稳定 blockId、内容或持久结果引用                     | 支持 text/source/fields/preview/action/lesson；旧纯文本消息作为 text 渲染  |
| `AssistantAction`         | 操作类型、目标、参数摘要、期望版本、确认状态、幂等标识、结果引用 | 状态为 pending/running/succeeded/failed/canceled/expired；执行前重新校验   |
| `AssistantLessonProgress` | 教程 id/version、当前步骤、尝试记录、完成证据                    | 与业务任务状态独立；教程升级时可以读取旧进度或说明需要重做的步骤           |
| `AssistantPreference`     | 帮助方式、讲解详细程度、语言                                     | 按当前用户与工作区隔离；允许恢复默认，不推断或持久化人格画像               |

意图标签建议为 `explore / collect / learn / diagnose / use_data`。采集阶段另存为 `clarify / source / fields / preview / review / result`，用于界面呈现和下一步建议；不能以阶段标签替代实际预览凭证或业务状态。

上下文由“近期消息 + 已确认目标摘要 + 当前资源最新摘要 + 必要工具事实 + 本轮知识片段”组成。事实携带来源、时间与资源版本，区分用户要求、工具观察和待验证推断。按内容长度与模型上下文预算截断；摘要不能授予操作权限，也不能替代执行前读取最新资源。

迁移与兼容要求：

1. 新增 SQLite 增量迁移，覆盖新字段、关联、卡片、操作与教程进度；不修改已有迁移文本或 checksum，不清空现有 1.0 数据。
2. 当前 Repository 存在针对 `001-conversations` 的迁移逻辑，需要与插件迁移目录一并改为顺序执行新增迁移，验证重入和中断恢复。
3. 已有 `committed` 会话映射为可继续聊天的生命周期，并保留原任务链接；已有 failed 会话保留失败 Turn 和错误信息，同时允许新的提问。
4. 已有草稿按原逻辑接入统一 Collection Draft；新建纯聊天不产生草稿，首次调用采集写入工具时才幂等创建并关联。
5. 保留旧 API 的响应和状态适配。旧接口仍可维持原草稿必需行为，新会话接口允许无草稿；避免破坏依赖 `draft.revision` 的旧客户端。
6. 新工具需同步更新类型、工具注册、数据库名称约束、迁移、协议和测试。不能只修改提示词或 TypeScript 联合类型。
7. 新会话按认证主体隔离；没有身份插件的 Desktop 使用本机工作区主体。历史记录没有可信所有者时保持明确的旧工作区访问范围，不把历史数据随机归给当前登录用户；访问策略、管理员行为和事件过滤在 P0 固定并测试。

## 5. 结构化操作与接口

消息内容和可执行行为分开。模型可以请求展示卡片或提出业务操作，但由服务端从已验证事实生成卡片，并注册可执行的 `actionId`。前端仅渲染固定组件和允许的路由锚点，不执行模型生成的 HTML、脚本或任意链接命令。

操作记录绑定用户、会话、资源和版本。正式执行沿用业务接口的权限、ETag/If-Match 与幂等能力。相同 actionId 的重复点击、网络重试和服务重启复用同一业务结果；执行失败与会话失败分开记录。用户改了字段或执行目标已变化时，旧卡片说明失效原因并提供重新准备入口。

建议新增接口如下，名称在 P0 契约阶段固定，均归 `ai-assistance` 所有：

| 方法与路径                                                  | 用途                                               |
| ----------------------------------------------------------- | -------------------------------------------------- |
| GET `/api/v2/assistant/capabilities`                        | 返回当前可用能力、模型连接状态、固定引导与练习能力 |
| GET / POST `/api/v2/assistant/conversations`                | 分页读取或创建可无草稿的会话                       |
| GET / PATCH / DELETE `/api/v2/assistant/conversations/{id}` | 读取、修改标题/偏好/归档状态、删除会话             |
| GET / POST `/api/v2/assistant/conversations/{id}/messages`  | 分页读取消息和卡片；发送消息并返回 Turn            |
| PUT `/api/v2/assistant/conversations/{id}/context`          | 校验资源引用并更新当前帮助对象                     |
| POST `/api/v2/assistant/turns/{id}/cancel`                  | 中止本轮；保留已完成业务结果                       |
| POST `/api/v2/assistant/turns/{id}/retry`                   | 重试失败或取消的轮次，重新读取最新上下文           |
| GET `/api/v2/assistant/actions/{id}`                        | 恢复操作状态和结果                                 |
| POST `/api/v2/assistant/actions/{id}/execute`               | 执行已展示且有效的具体操作                         |
| GET `/api/v2/assistant/lessons`                             | 列出当前版本和环境可用教程                         |
| POST `/api/v2/assistant/conversations/{id}/lesson-progress` | 提交步骤事件并返回经校验的进度                     |

会话和上下文更新使用自己的 revision，不复用草稿 revision。读详情返回恢复所需的当前 Turn、有效卡片和关联资源摘要。写请求使用 Idempotency-Key；需要防止覆盖的资源更新使用 If-Match，错误沿用 RFC 7807。

沿用现有 SSE 通道注册助手事件。文本增量允许仅实时传递；最终消息、卡片、操作结果、教程进度必须落库。断线重连以持久状态补齐，事件携带 conversationId/turnId/blockId 或 actionId 并去重。订阅推送和详情读取采用相同访问范围，退出账号时清理连接与 UI 查询缓存。

## 7. 贯穿实施的工程约束

### 7.1 小量预览与执行预算

预览返回最多若干行与实际请求范围是两件事。首版建议默认预览最多 2 页、最多展示 10 行、单次预览 30 秒，具体值在 P0 对静态和动态样例测量后固定为产品常量。详情请求、浏览器加载和嵌套模型调用必须计入预算，不能仅截断返回数组。

沿用现有 Turn 上限作为起点：8 个模型轮次、12 次工具调用、120 秒；教学讲解通常不需要浏览器资源。AI Turn 的资源类别不能继续一律为 `browser-heavy`，应区分普通对话与页面检查，并验证不会因父子 Job 互相等待而占满资源。

默认同一失败原因自动尝试一次有依据的修复；仍失败则说明已做什么、卡在哪里、能采取什么操作。正式运行使用 Platform Job 自身预算和持久进度，不以一个 AI Turn 的存活承载长时间采集。取消会停止未完成调用，但已成功提交的业务动作仍显示真实结果。

### 7.2 数据、访问与事实来源

页面正文和搜索摘要按不可信数据处理，不能改变工具权限。继续沿用网络策略、凭据存储与脱敏机制；工具结果、持久消息引用和事件订阅均校验访问范围。模型只接收完成本轮必要的摘要或样本。

预览、正式结果、教学样例和模型建议必须清楚区分。未知记录总数显示未知；样本缺失率不描述为全量质量；模型无法仅根据一条成功日志断言所有字段准确。准备、运行和成功的界面状态以实际业务状态为准。

### 7.3 迁移和发布回退

新增能力按阶段开关控制，配置进入现有 Profile/配置机制。关闭新入口保留会话、草稿、规则和数据；旧 API 适配仍可处理既有任务。操作执行状态需在开关变化和 Runtime 重启后继续查询。

数据库升级采用增量和兼容方式；不能未经验证直接降级到旧二进制并假定新 Schema 可读。优先关闭新功能并向前修复；若必须二进制回退，先验证支持的 Schema 版本和正在执行的操作处理方式。

### 7.4 工作区和验证

实施开始记录已有工作区修改，在其基础上追加改造，不清理用户改动。测试使用独立数据库和 Desktop 用户目录，不重置原开发实例，不篡改现有迁移记录。

UI 复用现有设计系统和国际化；覆盖 360/768/1024/1440px，关注侧栏焦点、键盘入口、Escape、焦点恢复、表格局部滚动和流式消息无障碍播报。只为真实业务约束和错误路径补充必要测试，不为文案改动添加实现镜像测试。

## 9. 用户验证与指标

延续[用户测试脚本](usability-test-script.md)，为助手增加四个目标任务：从模糊想法获得可用表格、已有网址提取指定三列、完成教学后独立做一个相似练习、处理一次字段缺失或输出失败。主持人记录帮助次数、耗时、回退、误解、结果检查和参与者原话。

| 指标           | 口径                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------- |
| 助手采集启动数 | 会话明确进入采集意图时记录一次 attempt；纯问答不计入，改变为独立目标时创建新 attempt     |
| 首次预览完成率 | 获得有效、非空预览的采集 attempt / 采集启动 attempt；有效预览不等同于业务语义正确        |
| 首次正确结果   | 在用户研究中按预定字段和记录核对；产品内用户反馈单独记录，不能由模型认定                 |
| 首次结果耗时   | 同一 attempt 从采集开始到首次成功运行的耗时中位数，并展示未完成数量                      |
| 结果使用率     | 已成功任务中发生服务端确认的导出、分析或同步的比例，沿用原产品口径                       |
| 失败恢复率     | 已进入诊断且在规定观察期内完成对应修复结果的案例比例；恢复结果需关联原失败和后续业务操作 |
| 教学独立完成   | 用户研究中无额外提示完成相似练习的情况；产品教程完成数只说明步骤完成                     |

attempt 与后续 draft/task 的关联在服务端持久化并去重。学习样例统计进入单独口径，不混入真实采集转化。指标保留管理员开关、清除和 90 天保留期，不保存提示词、网址、字段值、页面内容或凭据。无样本显示“—”，同时展示样本量与观察期。

第一轮用于获得基线与发现阻碍，不预先虚构完成率。正式推广前修复观察中无法完成核心任务的阻断项，再依据基线确定下一轮量化目标。
